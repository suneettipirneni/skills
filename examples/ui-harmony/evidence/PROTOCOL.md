# Fresh-context React generation evaluation

Goal: verify that a conversation using UI Harmony can produce React web interfaces with polish comparable to the user's references, with Untitled UI as the principal aesthetic anchor.

Two independent fresh-context agents receive the frozen skill snapshot, a realistic task brief, output directory, runtime port, optional actual reference captures, and permission to implement/inspect a local React demo. They do not receive the prior diagnosis, desired composition, scoring targets or hidden CSS instructions. Their EVALUATION.md records reference/skill usage and checks. Both use the inherited model/settings; no model override is introduced.

Cases: Gather team management (search, filter, invite with validation, confirmation and recovery); Relay subscription analytics (period changes, coherent data/chart, customer drilldown preserving context, empty state). They exercise distinct collection/form and analytical idioms.

Reference observations are relationship anchors, not pixel-copy targets. Compare matched desktop1440×1000 and phone390×844 application views, plus relevant interaction states. A static Dribbble presentation may inform visible craft only. A task-first product may deliberately differ from a demo's arrangement, density or imagery.

Review criteria established before inspecting generated outputs:

1. Composition: hierarchy, shared tracks, proximity and pacing are deliberate; the main task owns the surface; no unexplained scaffold-like voids or equal-weight filler.
2. Typography/content: complete roles, readable metadata, intentional line endings and realistic domain content; no invented charts or entities used as decoration.
3. Component finish: optical icon/text balance, coordinated spacing and shallow material, distinct state treatment, coherent radii and shared seams where applicable.
4. Adaptation: narrow layout recomposes navigation, content and actions without lost task-critical data, awkward wrapping or page overflow.
5. Interaction: relevant loop works with clear feedback and recovery, keyboard/focus continuity and stable state geometry; visuals do not conceal unfinished controls.

Root visually inspects actual browser evidence and runs independent task/accessibility checks. Adversarial reviewer compares the outputs against the same reference qualities and identifies the strongest remaining mismatch, with location, evidence, consequence, proposed correction and preservation. Neither generator's self-assessment nor a style-fit total determines acceptance.

Acceptance is a supported expert judgment about these outputs and inspected states: no material visual/interaction gap remaining under the stated criteria, agreement of root and adversary with concrete reasons, working React build and scoped interaction/responsive/accessibility checks. Report disagreements, untested cases and uncertainty. This does not prove universal taste, participant delight, reliability on arbitrary prompts or statistical parity with an entire design system.

If outputs fail: identify the general skill/process gap, revise only justified guidance, and run the affected design conversation again using the revised skill. Preserve initial captures and distinguish agent self-refinement, reviewer-directed fixes, and any root-authored changes. Do not silently hand-polish generated CSS and attribute the result to the skill.

Skill snapshot: skill-v1/ with SHA256 manifest skill-v1-manifest.json. Subsequent installed changes adding direct explore/compose→untitled-ui route edges and recording the reference keyboard probe do not alter the frozen generation snapshot; document any later snapshot explicitly.

Artifacts currently local under /private/tmp/ui-harmony-evaluation. No real invitations, external messages or production deployments are part of this test.

User steering after the initial briefs: recommend headless component boilerplate such as Base UI. Both agents received the same optional recommendation, official documentation links and instruction to record it. The frozen skill-v1 itself predates the dedicated headless-primitives reference. Results therefore evaluate the frozen skill plus this explicit user instruction, not a pure skill-only ablation.

## Bespoke transfer phase

The user requested original applications rather than mimicking existing surfaces. Gather and Relay remain calibration cases; they are not sufficient evidence for this new scope. Two fresh-context generators now receive independent domain briefs: Margin, connecting research excerpts to findings with supporting and contradictory evidence; Cue, connecting actual podcast playback, chapters and timecoded review notes. Skill-v2 is frozen with its manifest. The subsequently added bespoke guidance is supplied explicitly and its timing recorded. No reference application's composition is specified.

Additional acceptance criterion: the object relationships must visibly shape the layout and state transitions. Identify the primary domain relationship, the operation it enables, and where this is represented in the screen. Familiar controls are welcome; novelty is not a score. Reject renamed dashboards, decorative domain imagery, fake playback, arbitrary confidence metrics and irrelevant summary cards. Compare craft at corresponding relationships and actual scale, not overall image similarity.

Cue receives root-authored synthetic speech, chapter timestamps and measured waveform peaks as domain data only. The original 53.318-second fixture contains no third-party content. Margin uses clearly fictional interview excerpts. Neither fixture is a user study. Root supplies no CSS or desired screen arrangement.
